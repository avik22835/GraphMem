API Reference

All endpoints are served at your base URL. Authenticate with X-API-Key: gm_sk_... header (or Authorization: Bearer <JWT> for key management).

Get API key → Try in Playground

Conversations

A conversation is the top-level container for a session. All memory nodes and topics belong to one conversation.

POST /conversations

Create a new conversation. Returns a conversation_id — pass this to all memory and topic calls.

Body

FieldTypeDescription
metadata optionalobjectArbitrary key-value pairs attached to this conversation.
request
POST /conversations
Content-Type: application/json
X-API-Key: gm_sk_...

{
  "metadata": { "user_id": "u_123" }
}
{
  "conversation_id": "3f7a1b2c-..."
}
GET /conversations

List all conversations. Returns node count and last topic recompute time.

GET /conversations/{conversation_id}/stats

Graph statistics for a conversation — node count, edge count, topic count, average degree, graph density.

GET /conversations/{conversation_id}/export

Export all memory nodes in a conversation as a JSON array.

DELETE /conversations/{conversation_id}

Delete a conversation and all its nodes, edges, and topics. Irreversible.

Memory

Memory nodes are prompt + response pairs. A node becomes complete once both parts are stored — at which point it is embedded and wired into the graph asynchronously via Lambda.

POST /memory/prompt

Store a user prompt. Returns a memory_id — pass this to add_response to complete the node.

Body

FieldTypeDescription
conversation_id requiredstring (uuid)Conversation this prompt belongs to.
content requiredstringThe user's message text.
timestamp optionalISO 8601Defaults to server time.
metadata optionalobjectArbitrary key-value pairs.
request
POST /memory/prompt
X-API-Key: gm_sk_...

{
  "conversation_id": "3f7a1b2c-...",
  "content": "How does async/await work in Python?"
}
{
  "memory_id": "9e4c3d2a-..."
}
POST /memory/{memory_id}/response

Attach the assistant's response to a pending node. This completes the node and immediately queues it for embedding + graph insertion via SQS → Lambda.

Body

FieldTypeDescription
conversation_id requiredstring (uuid)Must match the conversation from add_prompt.
content requiredstringThe assistant's response text.
timestamp optionalISO 8601Defaults to server time.
POST /memory/batch

Add up to 100 complete prompt + response pairs in a single call. All nodes are immediately queued for embedding. Use this to pre-load existing conversation history.

Body

FieldTypeDescription
items requiredarrayArray of up to 100 objects, each with conversation_id, prompt, response, optional timestamp_prompt, timestamp_response, metadata.
POST /memory/recall

The core retrieval method. Embeds the query, runs a multi-set graph traversal, applies a token budget, and returns ordered context ready to inject into your LLM. Returns the union of Set B (top-K by cosine), Set A' (threshold neighbours), Set C (Neptune 1-hop expansion), and Set R (recency guard).

Body

FieldTypeDescription
conversation_id requiredstringWhich conversation to search.
query requiredstringThe current user message or search query.
k optionalinteger 1–50Top-K nodes for Set B. Defaults to server config (5).
threshold optionalfloat 0–1Cosine similarity threshold for Set A'. Default 0.4.
strategy optional"semantic" | "semantic_recency"Scoring strategy for Set B. semantic_recency blends cosine with recency decay.
recency_alpha optionalfloat 0–1Weight of cosine vs recency when strategy is semantic_recency. Default 0.7.
recency_half_life optionalfloat (seconds)How fast recency score decays.
always_include_recent optionalinteger 0–20Always include last N nodes regardless of relevance (Set R). Exempt from token budget cuts.
max_tokens optionalintegerToken budget for the returned context. Nodes cut by relevance score first.
request
POST /memory/recall
X-API-Key: gm_sk_...

{
  "conversation_id": "3f7a1b2c-...",
  "query": "How does async/await work?",
  "k": 5,
  "strategy": "semantic",
  "always_include_recent": 2,
  "max_tokens": 2000
}
{
  "messages": [
    {
      "memory_id": "9e4c3d2a-...",
      "prompt": "How does async/await work?",
      "response": "async/await is built on coroutines...",
      "score": 0.921,
      "set_membership": "B",
      "timestamp_prompt": "2026-09-20T10:00:00Z",
      "token_count": 142
    }
  ],
  "total_tokens": 142,
  "strategy_used": "semantic",
  "node_count": 1
}
GET /memory/{memory_id}

Fetch a single memory node by ID. Returns prompt, response, timestamps, status, and metadata. Embedding vector is not included.

GET /memory/{memory_id}/neighbours

Return graph neighbours of a node — other nodes connected by a cosine-similarity edge above the given threshold.

Query params

ParamTypeDescription
threshold optionalfloatMinimum edge weight. Default 0.7.
limit optionalintegerMax neighbours to return.
order optional"relevance" | "timestamp"Sort order. Default relevance.
DELETE /memory/{memory_id}

Delete a memory node. If it belonged to a topic, that topic is marked dirty and will be re-evaluated on the next recompute.

Topics

Topics are message clusters auto-detected via Louvain community detection every 20 nodes. Each is labeled and summarized by Groq. Use them for fine-grained context control.

GET /topics?conversation_id={id}

List all topics for a conversation. Returns id, label, message count, status, and last active time. The entry point to all topic operations.

Query params

ParamTypeDescription
conversation_id requiredstringConversation to list topics for.
status optional"active" | "dormant" | "resolved"Filter by topic status.
GET /topics/current?conversation_id={id}

Returns the topic the conversation is currently in — based on the last complete message node, not the incoming query. Essential for agents that need to track topic shifts without sending a query.

Query params

ParamTypeDescription
conversation_id requiredstring
mode optional"centroid" | "hybrid" | "llm"How to compute topic match. llm and hybrid require summaries to exist. Default centroid.
GET /topics/{topic_id}/status

Returns "active", "dormant", or "resolved". Use this to filter which topics contribute to context — skip resolved ones, keep active, optionally include dormant. Directly controls how aggressively token savings kick in.

GET /topics/{topic_id}/summary

Returns an LLM-generated summary string for the entire topic. When a topic is relevant but not the primary focus, inject the summary instead of all its raw messages — significantly fewer tokens for the same semantic coverage.

GET /topics/relevance?conversation_id={id}&query={q}

Score all topics against a query and return the top-N most relevant, ranked by cosine similarity to their centroids. Enables two-stage retrieval: compare against T topic centroids instead of N individual messages.

Query params

ParamTypeDescription
conversation_id requiredstring
query requiredstringThe prompt or search query.
top_n optionalinteger 1–20How many topics to return. Default 3.
GET /topics/{topic_id}/messages

Retrieve all memory nodes that belong to a single topic. Optionally narrow further with a query, and apply a token budget.

Query params

ParamTypeDescription
conversation_id requiredstring
query optionalstringFurther narrow results by similarity.
max_tokens optionalintegerToken budget for returned messages.
POST /topics/retrieve

Full two-stage retrieval in one call. Internally runs topics/relevance to find the top-N matching topics, then retrieves messages from each. The most token-efficient retrieval path — compare T topic centroids, not N messages.

Body

FieldTypeDescription
conversation_id requiredstring
query requiredstringThe current user prompt.
top_n optionalinteger 1–20How many topics to pull from. Default 3.
max_tokens optionalintegerTotal token budget for the returned messages.
GET /topics/{topic_id}

Full topic object: label, description, summary, coherence score, is_mixed flag, sub-themes, status, message count, last active, is_dirty.

POST /topics/recompute?conversation_id={id}

Manually trigger Louvain clustering + Groq labeling for a conversation. Topics are auto-recomputed every 20 nodes — use this to force an early recompute.

Auth

Key management endpoints require a Cognito JWT (Authorization: Bearer <id_token>), not an API key.

POST /auth/keys

Create an API key. The full key is returned once — it cannot be retrieved again. Requires JWT.

Body

FieldTypeDescription
project_name optionalstringA label for this key.
permissions optionalobject{"read": true, "write": true}
GET /auth/keys

List all API keys for the authenticated Cognito user. Full key values are never returned — only prefix, status, and metadata.

DELETE /auth/keys/{key_id}

Revoke an API key immediately. Requires JWT. The key is marked inactive — any requests using it will return 401.

Utils

POST /utils/count_tokens

Estimate the token count for any string using the same tokenizer GraphMem uses internally for token budgeting.

Body

FieldTypeDescription
text requiredstringText to count tokens for.
GET /health

Liveness check. No auth required. Returns {"status": "ok"} when the API is up.
